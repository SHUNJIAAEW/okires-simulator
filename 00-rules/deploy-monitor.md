# 00-rules/deploy-monitor.md — デプロイ監視・自動ロールバック設計

> Vercel 等のデプロイ失敗を検知し、ログを取得して原因特定・ロールバックまでを半自動化する仕組みの設計メモ。
> 現状は構想段階。優先度: 中（手動でも回るが、自動化で大きく時短）。

## 目的

- デプロイ失敗 → ログ取得 → 原因特定 → ロールバック の手作業を削減
- 失敗の根本原因を mcp__memory に蓄積し、再発を防ぐ

## 既存資産の確認

| 機能 | ツール | 状態 |
|---|---|---|
| デプロイ状態取得 | `mcp__e1d0e4e0-...__get_deployment` | ✅ 接続済み |
| ビルドログ取得 | `mcp__e1d0e4e0-...__get_deployment_build_logs` | ✅ 接続済み |
| ランタイムログ | `mcp__e1d0e4e0-...__get_runtime_logs` | ✅ 接続済み |
| デプロイ一覧 | `mcp__e1d0e4e0-...__list_deployments` | ✅ 接続済み |

**結論**: カスタムMCPを新規実装する必要はない。既存の Vercel MCP を組み合わせれば監視ロジックを書ける。

## フロー設計

```
[人間 or cron] → デプロイ実行
                    │
                    ▼
            [定期チェック]                    （07-routines/ に cron 登録）
                    │
                    ▼
            状態 = "READY" → 完了 ✅
            状態 = "ERROR" → 以下に進む
                    │
                    ▼
            [build/runtime log 取得]
                    │
                    ▼
            [エラー署名で mcp__memory 検索]
                    │
                    ├─ 過去事例ヒット → 解決策を提示
                    └─ 未知エラー → 人間に通知 + 新規記録
                    │
                    ▼
            [ロールバック判断]
                    │
                    └─ 人間承認後に前バージョンへ戻す（不可逆操作）
```

## 担当エージェント

`web-builder` または新規 `deploy-monitor`（必要になれば作成）。
当面は `web-builder` の責務に含める：

```yaml
追加責務:
  - Vercel デプロイ後 5分以内に get_deployment で状態確認
  - ERROR の場合は build logs を取得し原因サマリーを報告
  - ロールバックは人間承認後のみ実行
```

## ルーチン登録（07-routines/）

実装時は `07-routines/deploy-monitor.md` を作成し、cron で：

- デプロイ後 5分・15分・30分の3回チェック
- ERROR 検知時のみアラート
- 連続成功時は cron 自動停止（無駄チェック削減）

## 安全規則

- **ロールバック実行は人間承認必須**（不可逆操作）
- **本番環境への自動操作は最初の30日は完全人間承認運用**で習熟後に自動化を検討
- ログ取得は読取のみ＝自動で良い

## 状態

**現状**: 設計のみ。実装は web 案件のデプロイ頻度が上がってから着手。
**着手条件**: 月3件以上のデプロイ失敗 or 人間の障害対応工数が月5時間超え
