# 00-rules/drift-detection.md — エージェント迷走（ドリフト）検知ルール

> 自律型エージェントが「無限ループ」「同じ修正を繰り返す」「正常コードを破壊」状態に陥ったとき、
> どう止めて、どう再起動するかのプロトコル。

## ドリフトのサイン（即停止条件）

以下のうち**1つでも**該当したら、エージェントは作業を止めて人間に報告する：

1. **同じ方向のパッチを3回以上当てたが解決しない**
2. **同じファイルを5回以上 Read している**（自分の context を信用していない）
3. **同じエラーメッセージが3連続で返ってくる**
4. **既存の正常コードを「リファクタ」名目で削除し始めている**
5. **次のアクションを「なぜ」説明できない**
6. **prompt がどんどん長くなるのに前進していない**

## 規模別の対処

| ドリフトの規模 | 対処 |
|---|---|
| タイポ・変数名ミス | その場で修正してよい |
| ロジックの軽微なバグ | その場で修正してよい |
| **設計の前提が間違っていた** | **会話を捨てて新セッション** |
| **同じ方向のパッチ3回以上** | **一度立ち止まり、根本設計を見直す** |
| **無限ループ** | **即停止＋人間にエスカレーション** |

## 解決策

### 解決策1: コンテキストの強制リセット

履歴が「失敗した推論」に引きずられているとき：
1. 現セッションで「何が間違っていたか」を1行で `.claude/memory/MEMORY.md` に記録
2. 該当する `AGENTS.md` / `CLAUDE.md` / `_RULE.md` を更新（次回防止）
3. 新セッションを開き、クリーンな状態から再開

### 解決策2: 制約の追加（ガードレール）

エージェントの自由度が高すぎると迷う。以下を `AGENTS.md` / 該当エージェント定義に追記：

- 「このディレクトリは編集禁止」
- 「このライブラリは使用しない」
- 「次のフェーズは XYZ。先に進まないこと」

### 解決策3: 人間による「一歩手前」のガイド

100%の自律 < 95%の自律 + 5%の的確なヒント。
複雑なバグでは「このファイルの15行目付近を見て」とヒントを与える方が、エージェントに考えさせるより速い。

### 解決策4: 別エージェントによる第二意見（Codex併用）

Claude Code が迷走しているときは `codex` skill で Codex に同じ問題を投げ、別視点を得る。

## エスカレーション基準

| 状況 | エスカレーション先 |
|---|---|
| 同じパッチ3回失敗 | オーケストレーター（Claude本体） |
| 設計前提が崩れた | 人間 |
| 不可逆操作の判断 | 人間（必ず） |
| 部署横断の判断 | 該当部署の CxO |
